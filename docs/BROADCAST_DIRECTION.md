# Broadcast Direction v2

Synthesis of four research tracks (broadcast rundown craft, Qwen3-TTS delivery control, MToon/VRM presentation, credibility & continuity devices) into a prioritized build plan. Organizing principle: **one field, many outputs** — a single piece of rundown metadata (role, mood, tone) should simultaneously drive writing, voice, face, camera, and timing. Second principle: **the Base TTS checkpoint cannot take instructs** (clone+instruct is an open mlx-audio feature request, issue #453), so all delivery control this quarter routes through writing, reference-clip selection, and playback timing — never through stage-direction text.

---

## Tier 1 — This week (small code, big feel)

### 1.1 Broadcast-copy rules in the ON AIR prompt + a lint pass
- **What:** Add hard writing constraints to the segment/bulletin prompts: one thought per line, 15–20 words (reject >22), subject-verb-object active voice, contractions, direct address, no semicolons/colons, no "officials stated that…" constructions, present/present-perfect leads with daypart words ("this morning", "within the last hour"), rounded numbers spoken ("nearly two billion dollars", never "$1.9B"), attribution up front ("The filing says—"). Deliberately vary sentence length: a 4–6 word punch sentence after a 20-word setup, never three same-length sentences in a row; em-dash for beat-and-pivot, ellipsis mid-line only (never line-end), max one exclamation per segment. Then add a mechanical lint between generation and `composeBulletin`: split lines over ~22 words, strip banned punctuation, spell out digits/symbols.
- **Why:** NPR Training ("speak it before you write it", 15–20 words) and Media Helping Media radio-script rules; Qwen3-TTS conditions prosody on raw text semantics and punctuation, so this is the highest-leverage zero-cost expressiveness fix — `voicebox.js` currently does **no** normalization beyond whitespace collapse.
- **Where:** `src/brain/index.js` — `PERSONA` (line 30) and `segmentPrompt()` (line 154); lint function in `src/anchor.js` applied before `composeBulletin()` (line 285); number/symbol spell-out as a final safety net in `src/voicebox.js` `renderLine()` (line 326, currently only `.replace(/\s+/g,' ')`).

### 1.2 Content-driven camera cuts (kill the round-robin)
- **What:** Replace `const SHOTS = ['med','close','screen','close']` (cycled by line index) with a per-line chooser run before each `say()`: `screen` only when the line cites evidence (regex for digits, "wire", "per <source>", source names from `seg.sources[]`); `close` for the lead's strongest line and breaking pulses; `wide` for open/handoffs/signoff; hold `med` otherwise. Guards: never cut mid-thought without motivation, never the same shot twice in a row unless motivated, hold anchor shots 8–25s, cut on story boundaries (that's where real directors take Camera 2).
- **Why:** The JCOMA study of four AI anchors found content-blind repetitive kinesics is *the* documented uncanny tell; GDELT's 812-hour study shows news' fast feel (4.8s avg shot) comes from graphic inserts, not cutting around the anchor (anchor reads hold 10–25s, OTS units ~20s).
- **Where:** `web/ui.js` — `SHOTS` at line 444 and the `cut()` call at line 496, inside the existing per-line playback loop (lines 468–505). Pure UI change; no pipeline touch.

### 1.3 Lighting & renderer numbers (the MToon studio look)
- **What:** Enforce exactly **one** shadow-casting `THREE.DirectionalLight` on the avatar, intensity `Math.PI` (the r155 physical-units gotcha), positioned 30–45° camera-side, 15–30° above eye line. `renderer.outputColorSpace = SRGBColorSpace`, `toneMapping = NoToneMapping` (or `toneMapped=false` on MToon materials only if the set needs ACES). Material-side "fill": skin `shadeColorFactor` = lit color darkened 15–25% hue-shifted warm (never gray), `shadingToonyFactor` 0.5–0.7, `shadingShiftFactor` +0.1..+0.3 (emulates TV 2:1 key:fill). Backlight rim via `parametricRimColorFactor` cool white-blue, `fresnelPower` 4–6, `lift` ~0.1, `rimLightingMixFactor` 0.7–1.0 — a physical spot cannot rim a toon shader. Put any set-dressing spots on a non-avatar layer (`light.layers`). Add a lil-gui debug panel over `vrm.materials`.
- **Why:** MToon is a single ramp on dot(N,L) expecting one directional light (VRMC_materials_mtoon-1.0 spec; three-vrm official example is exactly one white directional at `Math.PI`; multi-light is buggy — three-vrm fix #801, GLES2 malfunction). ACESFilmic muddies flat toon albedo (three.js forum #15484).
- **Where:** `web/newsroom.js` — scene/light/renderer setup and VRM material load path.

### 1.4 Playback beat map (pauses are the player's job)
- **What:** Insert per-gap silences in the playback loop keyed to line type: ~250ms between script lines, ~500ms after a handoff, ~700ms before signoff, ~900ms hold before a `mood: 'breaking'` lead. Optionally mix a soft breath sample (clipped from a render) at low gain before lines >15 words.
- **Why:** In a render-per-line pipeline the model can't own inter-line timing — and shouldn't: long generations are where Qwen3-TTS's documented failure modes live (random laughing/humming, loops). Player-side gaps are deterministic and free.
- **Where:** `web/ui.js` — the `say()` loop, lines 468–505; keyed off the same per-line role/mood metadata as 1.2.

### 1.5 Reference-clip hygiene + runaway-render caps
- **What:** Audit `voices/*.wav`: trim each golden clip to its best 10–15s span (the canonical ~45-word `FALLBACK_REF_TEXT` reads ~16–20s, over the sweet spot), append 0.5s trailing silence, update `voices/transcripts.json` to the exact trimmed text. In the worker, cap `max_new_tokens` proportional to text length (a 10-word line must never get the 2048 default ≈ 2.7 min) and pin `language='English'` if the API accepts it.
- **Why:** ocdevel field guide: 10–15s is the quality plateau, longer refs cause hangs/loops; the first generated token conditions on the ref's final phoneme (0.5s-silence fix); accurate ref_text lifts similarity 0.75→0.89. One-hour fixes that improve every render.
- **Where:** `voices/bright-anchor.wav`, `calm-pro.wav`, `vtuber-spark.wav`, `voices/transcripts.json`; `src/voice/worker.py` `render()` (line 69) and the job loop (line 144); `FALLBACK_REF_TEXT` in `src/voicebox.js` lines 29–32.

### 1.6 Never-freeze idle stack + speech motion
- **What:** Three desynchronized procedural layers that never fully stop: (1) breath — sine on chest/spine bones, 12–16 cycles/min, tiny shoulder rise; (2) sway — low-frequency Perlin on hips/spine, 4–8s wavelength, asymmetric amplitude; (3) face — randomized blinks averaging ~17/min (2–6s intervals, occasional double-blink) plus `VRMLookAt` micro-saccades (100–300ms retargets of a few degrees every 1–4s). During speech: keep all layers at reduced amplitude and add nod accents (2–4° pitch, 150–250ms) on RMS-envelope peaks of the current line's WAV, with angular-velocity clamps so nothing jerks. On every camera cut, delay her gaze retarget to the new camera by 200–400ms so she visibly "finds" it.
- **Why:** arXiv 2509.05023: a character that freezes after speaking reads instantly artificial; saccades "significantly improve realism" (Disney gaze work); media-training doctrine says anchors continuously move heads while talking (Forbes/TJ Walker); nods track speech effort (PMC "Noggin Nodding").
- **Where:** `web/newsroom.js` — animation tick; envelope extraction can run in `web/ui.js` from the decoded audio buffer it already has per line.

### 1.7 Open/signoff grammar: cold tease + invariant catchphrase
- **What:** Restructure `open` into two beats: a cold tease (one line per top story, withholding the payoff — "A number just moved on the chip market. I'll show you which one."), then her standing intro. Tease rules in the prompt: no "might/could", no hype adjectives, never restate the headline verbatim. Restructure `signoff` into three beats: one-line recap of the lead only, forward promise ("next update in fifteen minutes"), then a single invariant catchphrase — write it once, never vary it. Pass wall-clock time + daypart label into the prompts and ban absolute dates in speech.
- **Why:** NYFA stacking guide (A-block = tease → intro → top story; kicker video runs under signoff); Poynter tease rules ("you are what you tease"); Cronkite/Murrow — the catchphrase's power is invariance.
- **Where:** `src/anchor.js` open/signoff pools (open already cites `{n}` per CONTRACTS §2); `src/brain/index.js` prompt strings; clock/daypart injection at the `runCycle` call site in `src/research.js` (line 78).

## Tier 2 — Next sprint (structure, continuity, interaction)

### 2.1 Segment form vocabulary + word budgets + DESK NOTES depth rubric
- **What:** Replace uniform "headline + lines" with explicit forms: `brief` (2–3 lines, one preset), `reader` (4–6 lines, one cut), `feature` (8–15 lines, multiple cuts incl. screen), `roundup` (4–6 one-liners, cut per line), `kicker` (light closer, wide shot, signoff plays over it). Budget in words before writing (~180 wpm: 2-min show ≈ 360 words; open ~40, lead 120–200, briefs 30–60 each, kicker 40–80, signoff ~30) — a feature steals budget from briefs, which collapse into a roundup. Depth is decided by a DESK NOTES rubric scored per sweep item: impact, wire-beat **velocity** (her real signal — `S.wire.beats` derivatives), novelty vs coverage memory, unique deep-research material; 3+ high axes → trigger `runDeepResearch` + a `feature` slot. Log scores in DESK NOTES so depth choices are auditable. Layer daypart templates on top: morning roundup-heavy, midday update-driven, afternoon one-feature-allowed, evening flagship (feature + slower pacing + closer camera), overnight "while you were away" recap.
- **Why:** Journalism University: pacing comes from varying story form, not order; ~540 words ≈ 3 minutes; Fiveable news-values rubric for depth; Nielsen dayparts + Pew — five distinct structural feels per day for free, and the mechanical answer to "in-depth when a story deserves it".
- **Where:** `src/anchor.js` — segment builder and `composeBulletin()` (line 285) gain `role`/`form`/`budget` fields; `src/research.js` `runCycle()` (lines 78–265) does the ranking/stacking (LEAD/BRIEFS/KICKER); `src/brain/index.js` `segmentPrompt()` gets per-form templates; `web/ui.js` maps `role` → camera/pause behavior (extends 1.2/1.4).

### 2.2 Developing-story continuity (the 96-shows fix)
- **What:** Per-slug coverage state persisted alongside the bulletin index: last-led angle, consecutive-appearance count, prior headlines with timestamps. Rules: a recurring story must re-lead with its newest development, never the same top line; after ~3 bulletins with no new wire activity, demote to a one-line "still watching" or drop; every recurrence opens with a reset line referencing her own coverage ("At the top of the hour I told you X — there's movement"). Inject prior coverage into the segment prompt ("Earlier coverage at 14:40: '<headline>'; report only what is NEW"). UI: chyron kicker "DEVELOPING · 3rd UPDATE"; segment card gains a small timeline strip of her earlier headlines. Deep research plays the all-news "check-call" role: run it on the running lead between bulletins so the next cycle has genuinely new material.
- **Why:** All-news radio wheel doctrine — never repeat a bulletin verbatim, 3-use cap on voiced reports (BBC 1981 checklist), Media Helping Media "old news is no news"; RTDNA continuity devices. This is the single biggest lever for making 96 daily shows feel like one anchor's continuous day, and it builds visible memory (parasocial trust).
- **Where:** `src/research.js` `runCycle()` — coverage-state read/write via `src/store.js` (bulletins index, CONTRACTS §4); prompt injection in `src/brain/index.js`; chyron + timeline strip in `web/newsroom.js`.

### 2.3 Mood bank + per-segment mood routing
- **What:** Extend the mood vocabulary from `developing|steady` to `breaking / developing / steady / quirky / wrap`, decided at DESK NOTES time. Build a per-identity mood bank by **self-cloning**: condition Base on the existing golden clip, render emotionally-written passages (short exclamatory sentences → urgent; long ellipsis-paced → somber), cherry-pick, save as `voices/bright-anchor.urgent.wav` etc. (10–15s each, exact transcripts in `transcripts.json`). Extend the worker protocol to `{"op":"tts","text":...,"out":...,"mood":"urgent"}` selecting the mood ref; `voicebox.js` passes the segment's mood. Fan the one mood field out to all channels: ref clip (voice), writing directives (breaking = short declaratives, no subordinate clauses; quirky = one written-in-smile aside), beat-map timing (tighter gaps for breaking), camera bias (close for breaking) and VRM expression.
- **Why:** Base's ICL mode transfers **prosody**, not just timbre (Qwen3-TTS tech report; expressive ref → expressive output per ocdevel); self-cloning keeps timbre anchored where VoiceDesign drifts per call. One mood per segment, contrast between segments — how human newscasts read.
- **Where:** `src/anchor.js` line 262 (mood decision); `src/voice/worker.py` (mood→ref map, currently hardcodes `args.ref`/`args.ref_text`); `src/voicebox.js` `renderBulletin` job construction; `voices/` + `transcripts.json`.

### 2.4 Inline delivery tags → face, camera, and clip selection
- **What:** Have ON AIR emit a per-line tag (`[urgent] [wry] [measured] [smiling] [grave]`) that is (1) stripped before text reaches `worker.py`, (2) drives VRM `expressionManager` at **restrained** weights — 0.1–0.3 max, 'sad' 0.15 + slowed blink for grave, 'happy' 0.2 only on kickers/signoff, 'surprised' ~0.1 for genuinely breaking — lerped over 1–2s riding the camera cut, (3) overrides the segment mood clip where it differs. Never full-weight presets during hard news.
- **Why:** The Open-LLM-VTuber pattern (LLM emits expression keywords, excluded from TTS, drives the face) — the proven Neuro-sama-style architecture; viewers attribute emotion they *see* to the voice they *hear*, so shipping facial emotion makes identical audio sound more expressive. Broadcast affect is restraint (brow/eyes, not grins).
- **Where:** `src/brain/index.js` prompts; tag strip in `src/voicebox.js` `renderLine()`; expression weights + blink modulation in `web/newsroom.js`; tag→shot bias in `web/ui.js`.

### 2.5 Source cards + the evidence beat (say what you show)
- **What:** Before saying `script[j]`, match the line against `seg.sources[]` names; on match, pop a source card (name, item title, lens icon, age "3h ago") held for that line's duration — `newsroom.showSourceCard({source,title,lens,age})` — replacing reliance on the static "SOURCES · A · B · C" footer. Evidence beat: pass live per-beat counts into the segment prompt ("14 items crossed the {topic} wire this hour") so scripts cite real numbers; when a line cites the count, `cut('screen')`, flash the matching bar via `newsroom.highlightBeat(slug)` (cyan ring + brightness pulse), aim her `VRMLookAt` at the right screen for that clause (~15–20° head yaw), then return to lens. Exact figures go on screen; the spoken line rounds ("nearly fifteen") — which gives the screen cut its reason to exist.
- **Why:** Viblio study (arXiv 2402.17218): on-screen citations timed to claims measurably increase post-watch credibility; NBCU lower-third conventions; claim-visual alignment is rewarded, mismatch punished. The wire wall renders **real** data (newsroom.js lines 126–138) — her most credible prop, currently never referenced on air.
- **Where:** `web/newsroom.js` — new `showSourceCard`/`highlightBeat`, `drawRight()` (line 1223), footer at line 1109; line-scan in the `web/ui.js` playback loop; count injection in `src/research.js` → `segmentPrompt`.

### 2.6 Viewer mail + visible process
- **What:** Turn `/api/ask` into a mailbag: keep the instant panel answer, also queue asks; at ≥2 queued (or every Nth bulletin), append a "VIEWER MAIL" segment — question text on the wall card, "A viewer asks—" read aloud, answer from the existing wire-grounded ask pipeline, sources attached; panel shows queue position. For DEEP DIVE bulletins, show the machinery: one method line in the open ("The desk ran four angles; 41 items crossed, 8 made the cut" — counts already in the return value), angle list on the left screen during playback, extracted DESK NOTES as a wall card while she reads only the ON AIR text; mid-show pulls bridge with "I asked the desk to pull that thread — stay with me" while the existing research SSE visuals play.
- **Why:** Marshmallow/Weathernews LiVE prove pre-collected, filtered viewer content is the async-interaction format — live chat not required; Neuro-sama's audience loves watching the machinery work. Reasoning shown, not spoken.
- **Where:** `src/server.js` (ask queue); segment assembly in `src/anchor.js`; `src/deepresearch.js` (DESK NOTES extraction lines 117–121, SSE events lines 61–158); wall cards in `web/newsroom.js`.

### 2.7 Render QA: two takes for high-exposure lines + rolling context (flagged)
- **What:** For open/handoff/signoff lines only, render 2 takes and auto-select by heuristic: duration within 150–190 WPM band, no clipping, no internal silence >600ms, no output <0.8× expected; reject-and-retry catches truncation/loops silently. Separately, behind a config flag: **rolling context** — for line N, `ref_audio` = line N-1's rendered WAV (or golden + N-1 concatenated), `ref_text` = its text, so the model "hears" the sentence it just spoke and continues the arc instead of restarting an identical prosodic curve per line. Guards: total ref ≤15s, 0.5s silence pad, re-anchor on the golden/mood clip at every segment boundary. A/B against status quo before default-on.
- **Why:** Zero-shot run-to-run variance is documented (ocdevel) — cheap retakes at RTF≈1.25 remove the worst 10% of renders, which is where "sounds robotic today" lives. Per-line monotony's mechanical cause is identical-ref-zero-history; conditioning on preceding audio is exactly what VoiceStar (2505.19462), MagpieTTS-LF (2606.18485), and JoyVoice (2512.19090) formalize.
- **Where:** `src/voicebox.js` (take loop + heuristics); `src/voice/worker.py` (accept per-job ref override); config flag in `src/config.js`; RTF baseline in `docs/VOICE.md`.

### 2.8 Franchises + segues
- **What:** 2–3 named recurring segments scheduled by daypart: "The Wire Wall" (roundup read straight off real per-beat counts, screen preset), "Deep Dive" (the feature slot, consistent intro phrase, only when the 2.1 rubric fires), "Watching" (30s status check on topic-watch screens). Handoffs must name the actual relationship between adjacent stories (thematic/causal/geographic/deliberate contrast — "From markets to something completely different"); every segment's mandatory last line is a forward-looking `tag` ("The investigation continues tonight"), which doubles as the cut point; never "In other news" twice per show. Transition business: 1–2s look-down-at-desk at segment boundaries (paper-square animation, natural cover for the DESK NOTES gap).
- **Why:** NYFA — the B-block enterprise story is how a show differentiates itself; franchise names give viewers handles and the generator reusable molds; Journalism University tag/bridge grammar; IU floor-director conventions (the anchor's turn *is* the transition).
- **Where:** Prompts in `src/brain/index.js` (handoff prompt near line 575); `tag` field in `src/anchor.js`; franchise scheduling in `src/research.js`; desk-look beats in `web/newsroom.js`.

## Tier 3 — Requires training (prosody finetune hooks)

Design principle: everything in Tiers 1–2 (mood field, delivery tags, worker `mood`/ref-override protocol) is the **hook surface** — finetuned weights slot into the same interfaces later with zero pipeline change.

### 3.1 Speaker LoRA on 0.6B-Base
- **What:** LoRA-finetune `bright-anchor` into Qwen3-TTS-0.6B-Base for more stable prosody and no runtime ref clip. One-command paths exist: `github.com/sruckh/Qwen3-TTS-finetune`, `github.com/cheeweijie/qwen3-tts-lora-finetuning`. Output weights must be MLX-converted/quantized for the mlx-audio path. Hook: worker gains a `model` field per identity; `voicebox.js` config selects it.
- **Why:** Base is explicitly "designed for fine-tuning" with official single-speaker support; kills zero-shot run-to-run variance at the root.
- **Where:** New `bench/` training scripts; `src/voice/worker.py` model loading; `src/config.js` voice tiers; `docs/VOICE.md`.

### 3.2 Instruct distillation onto her voice
- **What:** Generate (instruct, text, audio) triples with 1.7B-CustomVoice/VoiceDesign in a bright-anchor-adjacent timbre, then LoRA 0.6B-Base on them — giving line-level instruct control ("slow, deliberate, dramatic pauses") on her own cloned identity, the thing the checkpoint family can't do today. The Tier-2 delivery tags become the instruct vocabulary verbatim, so nothing upstream changes.
- **Why:** Clone+instruct is a checkpoint boundary (Qwen3-TTS feature table: Base instruct ❌; mlx-audio issue #453 open, unanswered); distillation is the documented bridge.
- **Where:** Training pipeline outside the repo; consumption via the same `worker.py` protocol (`mood`/tag → instruct string).

### 3.3 No-training middle path + research watch
- **What:** (a) Benchmark the 9 Qwen3-TTS-12Hz-1.7B-CustomVoice timbres (mlx-audio `generate_custom_voice(text, speaker, language, instruct)`) as an opt-in "expressive" voice tier via a `voice.model` config switch — test 8-bit 1.7B for memory/RTF on the 8GB M-series floor (docs/VOICE.md) before offering; accepts losing the exact cloned identity. (b) Watch task-vector emotion merging (arXiv 2606.05367 — emotion-intensity dial by weight arithmetic, zero data) and TED-TTS (arXiv 2601.03170 — training-free intra-utterance control); either landing for this architecture obsoletes parts of 3.2.
- **Why:** Instruct-following is documented meaningfully stronger at 1.7B than 0.6B; task vectors would give an emotion knob with no training data at all.
- **Where:** `src/config.js` + `src/voice/worker.py` (CustomVoice branch); evaluation notes in `docs/VOICE.md`.
